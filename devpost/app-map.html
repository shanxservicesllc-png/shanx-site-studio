ShanX Site Studio

ShanX Site Studio helps someone create a simple local business page, choose between two genuinely different themes, see their edits, save their browser draft, and download a standalone HTML website. The app stays local. It does not use an AI service or require hosting.

Launch on MONSTER

From the project folder, run python -m http.server 8000 --bind 127.0.0.1 --directory app, then open http://127.0.0.1:8000/ on MONSTER. If Windows restarts, restart this server. Previously downloaded HTML pages open without the server.

One visible action, three source locations

This is a reference route showing how clicking Export HTML produces a real file; it does not claim someone already toured the code.

1. User clicks Exportapp/main.js

Event listener on #export runs the download function.

2. The file is builtapp/export.js

exportHTML serializes safe website markup. downloadHTML triggers the browser download.

3. The design is chosenapp/themes.js

siteTree and themeCSS supply the selected site's structure and CSS.

↓

Visible result: a self-contained .html file in Downloads that works offline.

Try the same route in source

  1. Open app/main.js and find $('export').addEventListener. It connects the button to the export operation.
  2. Open app/export.js and find export function exportHTML then downloadHTML. These turn user data into escaped HTML and request a real download.
  3. Open app/themes.js and find export function siteTree and export function themeCSS. These keep the two designs different beyond a color change.

To change something, start here

Opening or editor labels: app/index.html

Mobile Edit/Preview behavior: app/main.js, function setWorkspaceView, and app/styles.css, rule @media(max-width:900px)

Draft restore and erase: app/storage.js, functions readDraft, saveDraft, clearDraft

Exported site's look and layout: app/themes.js; both themes reuse app/export.js

Tests: tests/*.test.mjs, browser evidence under devpost/private-evidence/stage5-slice2 and stage5-slice3

A practice to reuse

Define success as something observable before calling a feature finished. In this project, the requirements in devpost/spec.md turned into actual checks: both distinct themes opened as downloaded HTML without network access; saved drafts restored; a narrow viewport showed Edit and Preview while desktop displayed both. This made it possible to distinguish tested behavior from assumptions, and to preserve the working result in Git before moving to another app.
